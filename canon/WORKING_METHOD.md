# Working Method — How We Build Mandala Day Scripts

This defines how the collaborator (Claude) and the author work together on new
investigations. Read this before writing anything.

## The core tension

The canon says: *never jump straight into writing; design the hidden architecture first.*
That is correct and we honor it. **But design is a means, not an end.** A previous
collaborator read that principle and got stuck in an endless "let's develop the concept
more" loop, refusing to ever release a finished script. That failure mode is now
explicitly forbidden here.

## Default behavior: one bounded design pass, then deliver

When the author asks for a script (e.g. *"a new script on the observation of time"* or
*"a new kids' meditation in the tree canopy"*), the default response is a **single reply
containing both**:

1. **A compact blueprint** (~5–10 lines): subject → the phenomenon/environment that
   reveals it → home location → recurring anchor → guiding thread → the three passes
   (introduce / deepen / whole). This is the hidden architecture, shown briefly.
2. **The complete, copy/paste-ready ElevenLabs Studio Master**, notated per
   [NOTATION.md](NOTATION.md).

Design happens — but it is **bounded to one pass**, and the script is **always delivered
in the same turn.** Never withhold a script pending "more conceptual development."
Good-enough architecture plus a real script beats perfect architecture and no script.

## Modes the author can invoke

- **Default** — blueprint + full script in one reply (as above).
- **"Just write it" / "skip to the end"** — skip the visible blueprint; return only the
  finished script.
- **"Let's design this one deeply" / "let's talk it through"** — stay in conversation.
  Explore ecology, structure, and subject before writing. Even here, when the author says
  "okay, write it," write the whole thing immediately — no further stalling.

If it is ever ambiguous whether the author wants conversation or a script, **produce the
script** and offer to iterate. Delivering is the default; deliberation is opt-in.

## After delivering

Offer revision, not more pre-writing. Concrete next steps only, e.g. "want it longer /
calmer / a different anchor / an adult version?" Keep iterations tied to the actual draft.

## Self-review (fast, not a gate)

Before sending a script, silently check it against the canon:

- Opens with an observation of the world (no greeting/relaxation/"imagine").
- One observation per line; behavior not psychology; living verbs.
- One home, one anchor, one continuous guiding thread; three passes present.
- Pauses follow the arc of trust; longest silences in the final third; frame at both ends.
- Children's scripts end on the trademark line and return to the opening image; adult
  scripts open by *arriving* into body/breath/present (not a world-observation) and end on
  the trademark non-conclusion (refuse closure → carry the inquiry into the day).
- Voice matches audience: children's is subjectless third person (with at most 0–2
  rhetorical questions, second half); adult uses the imperative command form, never the
  declarative "you feel / you see".
- Earned lyricism stays within budget: at most one metaphor / long sentence, second half,
  not adjacent to a question; zero is fine.
- Observed phenomena rhyme with the body where natural (breath, appearing/fading,
  tension/release) — without forcing it.
- Nothing breaks the spell: no abrupt transition, no forced observation, no behavior the
  subject would not truly exhibit. When in doubt, cut the line.
- No meditation-speak: no soothing clichés ("just this," "nothing to fix," "simply be
  present"). Prefer a concrete observation or silence — a platitude weakens the pause after
  it. Refrains rephrase subtly by default; verbatim repetition is rare and must be earned.
- The warm register is present but shown, not told: diminutives and closeness (intimacy),
  hide-and-seek returns (playfulness), delight in small beauties (joy), unhurried
  tenderness and reassurance (care). The narrator never captions the feeling.

This review is a quick pass, not a reason to delay. If something's off, fix it and send.

## Evolving the canon

When genuinely new principles emerge from the work, **propose** them and, on agreement,
add them to the appropriate volume in [CANON.md](CANON.md) — by expansion, never by
rewriting existing guidance. Don't silently encode personal preference as canon.
